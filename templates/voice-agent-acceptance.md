# 电话数字员工验收卡

用途：在测试前约定什么算完成任务，并为每一项结果留下证据。工作表起步版，不代表任何产品已经通过验收。

## 一 定义岗位和完成条件

- 业务场景与对象：
- 来电接待 / 回访 / 预约 / 其他：
- 一通电话应该完成的任务：
- 任务完成的系统证据：
- 失败、拒绝、信息不足时如何结束或转交：
- 试验周期、样本、基线与验收负责人：

例如：预约任务要分别检查“对话中确认了时间”和“业务系统中确实生成了有效预约”，两项单独记录。

## 二 按场景测试

| 测试场景 | 预期行为与通过条件（测试前填） | 录音或系统证据 | 通过 / 失败 / 未测 | 后续处理 |
| --- | --- | --- | --- | --- |
| 正常咨询、信息完整 | | | | |
| 客户打断、改口或改变需求 | | | | |
| 姓名、时间、数量等关键信息 | | | | |
| 不知道答案或资料冲突 | | | | |
| 查询、预约或写入业务系统 | | | | |
| 接口失败、超时或重复请求 | | | | |
| 客户拒绝、要求停止或转人工 | | | | |
| 挂断后的记录与交接 | | | | |

每个场景的样本量和通过阈值由任务风险、原有基线及业务要求确定，本卡不预设统一分数。

## 三 分开看三类指标

| 层次 | 示例口径 | 要防止的混淆 |
| --- | --- | --- |
| 对话 | 接通、理解正确、关键信息确认 | 听起来像真人，不等于完成任务 |
| 执行 | 系统操作成功数 / 应执行数 | 口头说“已办理”，不等于系统写入成功 |
| 业务 | 有效预约、到店、有效线索或成交 | 接通率、意向标签和最终成交不能互相替代 |

指标补全：分子、分母、周期、样本量、排除条件、证据位置。归因不清时先记录相关变化，不直接认定由 AI 带来。

## 四 上岗前写清交接

- 有权执行哪些动作，哪些必须交人确认：
- 哪些信息可以记录，保留多久，由谁访问：
- 失败怎样发现、怎样通知、谁接手：
- 费用上限、暂停方式与恢复条件：
- 验收决定、责任人、日期和剩余问题：

使用测试号码与适当授权的业务场景。公开记录不要包含客户号码、录音中的个人信息或系统凭据。
